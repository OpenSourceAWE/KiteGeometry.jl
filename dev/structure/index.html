System definition

A SystemDefinition holds one awesIO structure document. Its component types are generated by src/build.jl from the schema vendored at src/awesio/structure_schema.yml from the awesIO commit gen/awesio.toml records: one field per required column, in the schema's order, then one per optional awesIO column, which is nothing where a document leaves it out, each quantity's unit in its docstring. A document writes an optional column only where a row fills it. Segments, tubes and a wing's canopy name their material, a row of the materials block. Each table block's rows are Rows, found by their position or their name: system.points[:kite]. Rows holds any elements named by a Symbol that cannot change in place, block rows or a tool's own records; a name lookup takes constant time, and a write that would give two rows one name is refused. Blocks the schema does not name are kept in extras; a column it does not name is read only as a field of a registered model.

KiteGeometry.Metadata — Type
Metadata

The metadata block of a structure document.

  • name::String
  • description::String
  • note::String
  • awesIO_version::String: Version of this schema the file was written against.
  • schema::String
  • n_points::Int: Number of rows in the points block.
  • connectivity_sha::String: Lowercase hex SHA-256 of the connectivity. State recorded against the structure can quote it, so that state is never replayed against a structure that indexes differently. The preimage is ASCII and built in document order, in three sections: the number of points, then each segment's two endpoints as ONE-BASED row numbers into the points block; then the number of bodies, then each tube's two bodies as one-based row numbers into the bodies block; then the number of canopy faces, then each face's corners as row numbers into the points block. The numbers of one element are comma-separated and every field ends in a semicolon, so a lone number always opens a section. Three points joined in a row and spanned by one face, on two bodies joined by one tube, read 3;1,2;2,3;2;1,2;1;1,2,3;. Row numbers are one-based so that implementations in zero-based languages agree with each other; a reader that gets this wrong sees every file as a mismatch.

Frames

Positions are in the ENU world frame. Each wing gives the origin and rotation of its KA frame, the frame its aerodynamic mesh is drawn in, and pos_KA puts a world position into it. A KiteGeometry.WingFrame names the points that fix such a frame, KiteGeometry.wing_frame gives its rotation and origin from any positions of those points, and KiteGeometry.ref_position the weighted position of a set of reference points. Bodies joined by tubes move together; KiteGeometry.connected_body_groups says which bodies form a group.

SymbolicAWEModels' authoring YAML

SymbolicAWEModels authors a system in its wing's KA frame: points at pos_cad, tethers by their segment count and stretched length, variables shared between rows, and transforms that turn the whole to an elevation, azimuth and heading. load_authoring converts that dialect into a SystemDefinition placed by its transforms, and returns those transforms beside it, so structure_document writes the full-form document with no transforms in it. Each segment's stiffness and density become a linear material and a tube's breukels2011 law SymbolicAWEModels' Breukels constants. The columns the schema left to tools, such as a point's type and drag or a segment's damping and what it does in compression, are read only by the models SymbolicAWEModels registers, as the row authors them; a tether that gives a segment count reads its segments' model from its own row. A canopy_faces table with the schema's own columns states each wing's canopy: a face's wing, and its corners by name or index. A filled cell that neither the loader nor the row's model reads is refused, as load_structure refuses one, naming the block and its columns, and so is a block it does not read that holds rows; a row's idx, where it has one, must be its position. A column a dict row leaves out is an unset cell, which a model field holds only where it admits nothing.

KiteGeometry.resolve_material completes a segment's diameter, stiffness and density from what its row gives and the settings, as the loader does, and KiteGeometry.unit_stiffness gives the stiffness of a linear material at a diameter, or of a placed segment from its material. KiteGeometry.expand_tether! adds a tether's segments and inner points to rows a tool holds, as the loader does for a row that gives a segment count, its stiffness a number, a law's name or a callable force law, collected in a KiteGeometry.MaterialTable. KiteGeometry.line_segment makes one segment the same way, for a structure built row by row. KiteGeometry.tube_law_parameters gives the parameters a tube's material takes from its law, and KiteGeometry.parse_table reads the rows of a table in the authoring YAML's format, such as a block the loader leaves to the tool.

KiteGeometry.load_authoring — Function
load_authoring(path; set::Settings, name, ignore_l0=false) -> (system, transforms)
load_authoring(authored::AbstractDict; set::Settings, name, ignore_l0=false)

The SystemDefinition SymbolicAWEModels' authoring YAML at path describes, or the parsed authoring document authored, and its Transforms, as Rows. The definition is placed: design positions moved by its tethers' stretched lengths and then by the transforms, each wing's KA frame the authored frame moved with its body. Each transform holds the points and bodies it moves: those naming it, a tether's inner points that of its ends, and a wing's body its wing's, else the first transform. set gives what a row leaves out: segment material, and every winch's gear ratio and drum radius. Each distinct line material is named after the multi-variable giving it, else after its first segment. name is the metadata name, the file's by default for a path; ignore_l0 makes every rest length the placed length. Each non-empty block it does not read is kept as an extra block; one named after a block of the structure document, or holding a single value, is refused.

Transforms

A transform turns some of a system's points and bodies, its members, about a base: what it turns goes to an elevation and azimuth seen from that base, the azimuth running anti-clockwise from east towards north as atan(y, x) does, and the body it heads to a heading about the radial. Its base is a point moved to a base position, or what another transform turns, so one transform can be chained on another. The transforms are kept beside the definition rather than in it, and reposition! and transform_velocities act on a Pose, the positions and body frames a run holds.

KiteGeometry.Transform — Type
Transform

The rigid motion that takes some of a system's points and bodies from the frame they are authored in to their pose in the world. It turns its object, the weighted rot_point else the position of body, to elevation and azimuth seen from its base, and about that radial until the frame of body has heading. The base is base_pos, where base_point is moved to, or the object base_transform turns. References are indices into the system's blocks and into the transforms.

Placing

place! puts a definition where its transforms and its tethers say, from wherever it stands, whether a YAML load built it, it was built row by row in Julia, or a transform changed since it was last placed. It works on the definition's own rows and runs one sequence: every unset rest length to the length it has there, each tether with an init_stretched_length to that length and the rest length its init_tether_force or init_stretch_frac makes it, pulley rest lengths shared in proportion to their segments' lengths, the transforms, each body's points carried with it, and each wing's KA frame with the body it names. A body whose fixed is true stays where it is, and a point with a tube rides both of that tube's bodies. A tether without init_* columns keeps its rest lengths, and a placed definition placed again stays where it is.

system, transforms = load_authoring("kite.yaml"; set)
transforms[1].elevation = deg2rad(40)
place!(system, transforms)                        # the tethers keep their lengths
system.tethers[:main].init_stretched_length = 120.0
place!(system, transforms)                        # the main tether is now 120 m long
KiteGeometry.place! — Function

KiteGeometry.Material — Type
Material{M}

A row of the materials block. What the elements are made of, which a solver needs to build them and a viewer does not. A material is a stiffness law and that law's parameters, which fix how it deforms and what it weighs. The laws tools share are defined below as <law>_parameters, which fix their parameters' names and units and the curve they describe. Any other law is free: it names a model its readers implement, and that model fixes its parameters. A reader that does not implement a material's law cannot build the elements naming it.

  • name::Symbol: Unique name of the material.
  • law::String: Name of the stiffness law: linear, membrane or breukels2011 as defined below, or any law its readers implement.
  • parameters::OrderedDict{String, Any}: The law's parameters, by name, in the units the law gives them.
  • model::M: the model the model column names, else NoModel

Models

Every component T{M} carries a model::M: the parameters a tool attaches to a row by naming a registered model in its model column, one extra column per field of M that model_columns(M) names, in the units the model was registered with. A table without a model column reads the model registered for its block with default=true; the writer leaves the model column out where every row reads that default, and names each row's model otherwise. A row whose model cell is unset or names no registered model, or whose table has no model column and whose block has no default, is a NoModel component. A model column a table leaves out is unset, refused where its field cannot be nothing, and the writer leaves out a model column no row fills. Reading refuses a filled cell in a column neither the schema nor the row's model names, an unregistered model's name included; strict=false drops those columns with a warning instead. A parametric model registers its UnionAll, read through the outer constructor M(columns...) the tool defines, and the writer names every instance of it after that registration. A component reaches its model's fields as its own, so tube.EA reads tube.model.EA and tube.EA = 3e5 sets it.
